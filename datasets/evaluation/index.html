Common evaluation datasets

Suppose we pretrain a language model on books, articles, and code. It learns to continue text, but what has it learned to do? Start with a small test:

Which gas do plants absorb during photosynthesis?

  • A. Oxygen
  • B. Carbon dioxide
  • C. Helium
  • D. Hydrogen

Expected answer: B.

Give the model many held-out questions and count the correct answers. This is accuracy: 80 correct answers out of 100 questions gives 80% accuracy. An evaluation dataset supplies the questions and reference answers; a benchmark also specifies how to present them and score the responses.

Now remove the choices. Can the model produce “carbon dioxide” on its own? Supply a passage containing the answer: can it read the evidence? Ask why a plant grows differently in two conditions: can it combine facts? These changes test different abilities, even when all the questions concern plants.

That is why we need several benchmarks. A single score cannot distinguish remembering facts, following a narrative, doing arithmetic, and writing working code. This page develops those distinctions through concrete examples.

About the samples: benchmark samples below come from released datasets, with recorded answers or evaluation checks and source links. Long passages labeled “excerpt” omit part of the original context. Row numbers start at 1, excluding headers. Letter labels are added when choices are stored without them; math delimiters are adapted for display. The opening plant question is illustrative.

1. Text pretraining

Here, “text pretraining” means evaluating the capabilities of a text model during or after pretraining. It does not mean training on these test answers. The LLM datasets overview explains the distinction between training corpora and held-out evaluation data.

The 21 benchmarks below are grouped by the capabilities they assess. These are not exclusive stage assignments: SimpleQA, GPQA, MATH-500, and LiveCodeBench, for example, also appear in evaluations of post-trained models. A base model's ability to complete text and an assistant's ability to follow a request can produce different results on the same underlying questions.

1.1. How a next-token model takes a test

For our plant question, one evaluation can compare the probabilities of the candidate answers and choose the most likely. Another can ask the model to generate a response, then extract its answer. Those are different procedures.

Zero-shot means no worked examples are provided in the prompt; few-shot means a few examples precede the test question. Neither updates the model's weights. Chain-of-thought prompting asks for intermediate reasoning before the answer. Report these settings because they affect what the score means. Evaluation harnesses explicitly configure prompts, output types, and metrics. Harness task configuration.

As the tasks become richer, the scoring method changes:

Model's jobTypical scoringWhat a correct result establishes
Select an answerChoice accuracyIt selected the reference option
Produce a short answerNormalized exact match or a reference-based graderIts answer matched an accepted answer under that grading rule
Complete a passageFinal-word accuracy or target-word perplexityIt predicted the withheld continuation
Write a function or programExecution against testsIts program passed the supplied checks

The entries below specify which of these applies. A correct final answer alone does not prove that the model's explanation or internal reasoning is correct.

1.2. World knowledge & factuality

Start with what the model knows. Then separate recognizing the right fact from recalling it without choices, and from resisting a plausible falsehood.

1.2.1. MMLU — broad knowledge across subjects

Motivation: narrow language tasks did not reveal whether a model could use the breadth of knowledge encountered during pretraining. MMLU (Massive Multitask Language Understanding) evaluates factual knowledge and problem solving across academic and professional domains. Paper.

Size: 14,042 test questions across 57 subjects, including history, mathematics, computer science, and law. Each question has four answer choices. This excludes the development, validation, and auxiliary training splits. Dataset split sizes.

Metric: one headline accuracy (%) score, computed as correct answers ÷ total test questions × 100; higher is better. Each question counts equally, with no partial credit, so subjects with more questions contribute more to the overall score. Subject-level accuracies can also be reported. Original scoring code.

Sample (from the dataset):

MMLU test set, high_school_biology, row 3.

The energy given up by electrons as they move through the electron transport chain is used to

  • A. break down glucose
  • B. make glucose
  • C. produce ATP
  • D. make NADH

Answer: C.

Size: 12,032 test questions across 14 domains, with up to ten choices per question. The separate validation split contains 70 examples. Dataset splits.

Metric: one headline accuracy (%) score: correct answers ÷ total test questions × 100. Every question counts equally, with no partial credit; category-level accuracies can also be reported. Higher is better. Scoring code.

1.2.3. TriviaQA — retrieving a fact from evidence or memory

Motivation: evaluate factual question answering using naturally written trivia and independently collected evidence. Reading supplied evidence tests comprehension; finding the documents also tests retrieval. Withholding evidence tests closed-book knowledge recall. Original project.

Size: the unfiltered configuration has 11,313 validation questions and 10,832 test questions. Public closed-book evaluations commonly use validation; the reading-comprehension and verified subsets have different sizes, so the configuration and split must accompany the score. Dataset splits.

Metric: commonly one headline exact match (%) score: the percentage of answers matching an accepted reference after normalizing capitalization, punctuation, and articles. The original evaluator also reports token F1: for each answer, balance how many predicted words are correct with how much of the reference answer is covered, then average across questions. It uses the best match among accepted aliases. Higher is better for both. Scoring code.

1.2.4. SimpleQA — short answers that expose factual errors

Motivation: make factuality easier to grade by asking for one short, verifiable fact, while selecting questions that challenge strong models. “Simple” describes the answer format, not the difficulty. Original release.

Size: 4,326 questions in the original evaluation set. Dataset description.

Metric: a common headline is correct (%): answers graded correct ÷ all questions × 100. A reference-based model grader labels each response correct, incorrect, or not attempted. Reports can also show the latter two percentages and accuracy among attempted answers: correct ÷ (correct + incorrect). This distinguishes factual success from abstention; higher correctness is better. Grading procedure.

A newer two-option version uses choice accuracy, so name the version and metric. Scoring variants.

1.3. Commonsense & reasoning

These benchmarks range from understanding everyday situations to combining scientific facts, tracking changes, and solving multistep problems. Some questions mainly test knowledge; others require inference. Their scores describe performance on specific tasks rather than a single universal reasoning ability.

1.3.1. HellaSwag — choosing a plausible continuation

Motivation: test whether a model recognizes plausible event sequences, even when wrong continuations are fluent. Adversarial filtering selects machine-generated endings that models found difficult to reject. Original project.

Size: 10,042 labeled validation examples, commonly used for public model evaluation. The separate test set has 10,003 examples. Each provides four possible endings to an activity description. Dataset splits.

Metric: one headline accuracy (%) for the chosen scoring setup: correct endings ÷ evaluated examples × 100. Harnesses may report both raw accuracy and length-normalized accuracy (acc_norm). The latter adjusts answer likelihoods for ending length before choosing an ending; the final score still counts correct choices. Higher is better for both. Harness configuration.

Sample (from the dataset):

HellaSwag validation record ind=92.

A lady walks to a barbell. She bends down and grabs the pole. the lady

  • A. swings and lands in her arms.
  • B. pulls the barbell forward.
  • C. pulls a rope attached to the barbell.
  • D. stands and lifts the weight over her head.

Answer: D.

Metric: one headline accuracy (%): correct solution choices ÷ evaluated questions × 100. Higher is better. Some harnesses additionally report length-normalized accuracy, which adjusts candidate likelihoods for length before selecting the answer. Original scoring, Harness configuration.

Metric: one headline accuracy (%): correct yes/no answers ÷ evaluated questions × 100. Every question counts equally, with no partial credit; higher is better. Evaluation description.

1.6. Code

Code adds an executable check: a plausible-looking answer can fail when run. pass@k estimates the probability that at least one of kkk sampled solutions passes all tests for a problem. pass@1 concerns a single sampled attempt; pass@10 grants ten chances. Neither means the percentage of individual unit tests passed. The HumanEval evaluation defines and implements this approach. Paper, Evaluation code.

1.6.1. HumanEval — implementing small functions from specifications

Motivation: evaluate whether generated code works instead of whether it resembles a reference program, since different implementations can solve the same task. Original release.

Size: 164 Python programming problems, each with a function signature, a docstring specification, and tests. Dataset.

Metric: typically one headline pass@1 (%) score. A completion succeeds only if it passes all tests for its problem. With one attempt per problem, compute successful problems ÷ 164 × 100; with multiple samples, average each problem's fraction of successful attempts. Reports may also include pass@10 or pass@100, which estimate success with more chances. Higher is better. Scoring code.

1.7. Reading a scorecard without losing the meaning

Return to our plant question. Giving the model the supporting paragraph, providing five examples, or letting it search the web can each change the score. To compare two runs, keep the evaluation conditions explicit:

RecordWhy it matters
Model checkpoint and training stageA base checkpoint and an instruction-tuned checkpoint are different evaluated models
Dataset version, subset, and splitGPQA Diamond differs from GPQA main; MATH-500 differs from full MATH

Contamination means evaluation content has entered training data, weakening the interpretation of the test as unseen problem solving. Public test questions can be present even when nobody deliberately trained on the benchmark. Keep training splits separate from test splits and investigate overlap; newer dated problems help but do not guarantee a clean test. LiveCodeBench's evaluation motivation.

Small differences also need context: on 198 GPQA Diamond questions, one changed answer moves accuracy by about 0.51 percentage points. Multiple benchmarks may share underlying questions or skills, so averaging all 21 scores does not create 21 independent measurements of general intelligence.

2. Text post training

Post-training turns a text model into an assistant that can follow requests and act on them. Start with a response constraint, such as “use only lowercase.” Then carry that constraint through a conversation. Finally, give the assistant tools and check whether it actually completes the user's task.

These six benchmarks cover those steps. Their evaluation prompts are held-out tests, even when a project also releases separate data for training. Many tasks have no single correct wording: their samples below show the recorded checks or expected outcomes instead.

2.1. Instruction following

2.1.1. IFEval — following checkable instructions

Motivation: test whether an assistant obeys explicit requirements such as word limits, required phrases, or output format. These requirements can be checked with code, avoiding subjective judgments about whether a response “looks helpful.” Original project.

Size: 541 evaluation prompts covering 25 types of verifiable instruction. One prompt can contain several instructions. Released prompts.

Metric: four accuracy scores, all higher is better. Prompt-level accuracy counts a response as correct only if it passes every instruction; instruction-level accuracy counts individual requirements passed. Each has a strict version that checks the original response and a loose version that also tries small cleanup steps, such as removing an introductory line. A single reported “IFEval” number should identify which of these four it uses. These checks establish constraint compliance, not factual accuracy or writing quality. Scoring procedure.

Sample 1: letter case (from the dataset):

Check: the response must use lowercase letters. Record 1593.

Check: the response must contain no commas. Record 3615.

Motivation: an assistant may follow a request initially, then forget it when the user adds another requirement. Multi-IF extends IFEval into conversations and multiple languages to expose that failure. Original paper.

Size: 4,501 evaluation conversations across eight languages: English, French, Russian, Hindi, Italian, Portuguese, Spanish, and Chinese. Metric: the paper averages four accuracy scores: strict and loose instruction-level accuracy, and strict and loose conversation-level accuracy. The latter requires all applicable instructions from the conversation to be satisfied. Results are reported by turn and language; an overall number averages across turns and languages. Higher is better. A final-turn score and an all-turn average summarize different things, so keep that label with the number. Metric definitions.

Original dataset and evaluation code

Size: InfographicVQA, often shortened to InfoVQA, has 30,000 questions: 23,911 training, 2,801 validation, and 3,288 test questions, over 5,485 infographics.

3.5. Referring & grounding

Grounding connects a phrase to a location in an image. In the RefCOCO family, the usual task is to return a bounding box for the referred object. Intersection over Union (IoU) is the area shared by the predicted and reference boxes divided by the area covered by either box. A typical evaluation counts a prediction as correct when IoU exceeds 0.5.

The sizes below count referring expressions, not unique objects: several expressions can describe the same object. “RefCOCOB” and “RefCOCO+B” are interpreted here as the testB subsets, which contain non-person targets; testA contains people.

3.5.1. RefCOCO — locating the object described by a phrase

Motivation: test whether language identifies a particular object among nearby alternatives. Short expressions may use appearance or location, such as which person is on the left.

Size: the UNC evaluation splits contain 10,834 validation expressions, 5,657 testA expressions, and 5,095 testB expressions. The training split is separate.

Metric: one grounding accuracy per split: the fraction of expression–image queries whose predicted box passes the IoU threshold. Higher is better. A segmentation version predicts masks and uses different metrics, so label it separately.

Original RefCOCO family and split definitions, Expression counts in the ReCLIP paper

Reference 47, expression 136

3.5.2. RefCOCO+ — grounding without simple location words

Motivation: test appearance-based identification more strongly. Annotators were asked to avoid location words, encouraging descriptions of color, clothing, and other visible properties.

Size: 10,758 validation expressions, 5,726 testA expressions, and 4,889 testB expressions under the UNC split.

Metric: one grounding accuracy per split, using box IoU > 0.5. Average the binary outcomes across expressions; higher is better.

Original RefCOCO family and split definitions, Expression counts in the ReCLIP paper

Size: 4,889 referring expressions in testB, describing 1,798 target objects.

Metric: one testB grounding accuracy: the percentage of expressions whose predicted boxes have IoU > 0.5 with the reference. Higher is better.

3.5.6. PixMo-Points — pointing to the requested objects

Motivation: test whether a model can return the locations of every object matching a description. Points offer a simpler output than full boxes or masks and naturally support several matching objects.

Size: PixMo-Points-Eval has 436 test records, each an image paired with a target label and reference points/masks. This is the evaluation subset; the much larger PixMo-Points collection provides training data.

3.6. Spatial reasoning

These tasks distinguish a position on the flat image from a position in the depicted three-dimensional scene.

3.6.1. 3DSRBench — reasoning about three-dimensional relationships

Motivation: test height, depth, orientation, and relationships among several objects. A thing appearing higher in the image is not necessarily higher in the real scene.

Size: 2,772 original questions: 2,100 on natural COCO images and 672 on synthetic scenes viewed from common and uncommon viewpoints. The released natural-image evaluation expands questions into extra variants, so its 5,157-row table is not 5,157 independent original questions.

Metric: one overall accuracy plus category scores; higher is better. The official protocol combines circular choice rotations with FlipEval: a question must remain correct when its image is horizontally flipped and its answer adjusted as needed. These consistency checks make the result stricter than ordinary one-pass accuracy.

Original paper, evaluation protocol, Release and scoring script

Sample (from the dataset):

Consider the real-world 3D locations of the objects. Which object has a higher location?

  • B. red hat of the person in red in the back

Answer: B.

3.6.2. CV-Bench 2D — counting and locating objects in the image

Motivation: test basic visual skills using questions derived from established computer-vision annotations: counting objects and identifying their two-dimensional spatial relationships.

Size: 1,438 test questions in the 2D subset of CV-Bench, drawn from ADE20K and COCO.

Metric: one 2D accuracy: compute accuracy separately for ADE20K and COCO, then average those two scores equally. Higher is better. This source-balanced average need not equal the fraction correct across all 1,438 questions.

4. Multimodal posttraining

Once a model can interpret visual input, can it follow a precise request about it and use it to solve a difficult problem? These five benchmarks focus on assistant behavior and reasoning after post-training. They can also diagnose earlier checkpoints; they do not prescribe a training method.

4.1. Visual instruction following

4.1.1. MM-IFEval — following instructions tied to images

Motivation: test both how a response is composed and whether the model applies instructions to the right visual information. A correctly formatted answer can still fail if the model reads the wrong values from an image.

Size: 400 main evaluation questions: 300 compose-level and 100 perception-level. The released table has 687 rows because it also includes 287 auxiliary prompts used for comparative judging; those are not extra test questions.

Metric: one average score, with compose-level and perception-level breakdowns; higher is better. Compose-level responses receive the fraction of constraints passed, using code for mechanical checks and model judges for semantic ones. Perception-level responses are checked against reference answers. The overall score averages the main-question scores, so it can award partial credit.

Original paper, Evaluation code, Released records

Sample 1: composition constraints (from the dataset):

You are provided with an image which contains two pictures side by side. Your task is to identify the differences between the two pictures. Separate the differences with a semicolon. Please write between 50 and 70 words in total. Do not use any commas in the response. Use **bold** for the first difference mentioned and *italic* for the last difference mentioned. If the difference is the cars, don't mention their color. Each difference must be followed by a brief explanation of why it stands out or how it changes the scene.

Answer: 8.200.

4.1.2. MIA-Bench — obeying layered visual requests

Motivation: test whether the assistant can satisfy several requirements at once, such as describing the pictured activity in exactly two sentences while including a metaphor.

Size: 400 evaluation image-prompt pairs. The project's additional instruction-training data is separate from this benchmark.

Metric: one average weighted judge score, plus component breakdowns; higher is better. A model judge evaluates the instruction components using their recorded weights, which sum to 10 for each prompt. Average the resulting 0–10 totals; some harnesses normalize to 0–1 or 0–100. This is partial-credit scoring, not an all-or-nothing pass rate.

Original project and judge notebook

Sample (from the dataset):

Explain the activity taking place in the image using exactly two sentences, including one metaphor.

Recorded rubric: describe the activity (4 points), use exactly two sentences (3), and include a metaphor (3).

First released record

4.1.3. VisIT-Bench — useful responses to varied visual instructions

Motivation: test realistic requests such as explaining a pictured phenomenon or suggesting what to do with an object. The response must be useful for the request, beyond simply recognizing what is visible.

Size: 592 original image-instruction examples across 70 instruction categories: 574 single-image and 18 multi-image examples. The standard single-image evaluation uses 574.

Metric: the leaderboard reports win rate against a reference response and Elo, rather than one exact-match accuracy. A GPT-4 judge compares response pairs using an instruction-specific image description, with response order swapped to reduce position bias. Win rate summarizes preferences against a fixed reference; Elo summarizes comparisons across the evaluated models. Higher is better, but Elo depends on the comparison pool.

Official project and scoring explanation

Sample (from the dataset):

What are the bright little specks and what causes them to be bright?
