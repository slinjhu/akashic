Architecture

Akashic has three main layers: Markdown content, a generated content index, and a Next.js application. Notes stay in portable text files, while the app controls their layout, rendering, and interactions. Git records their history.

Content and metadata

The docs/ directory is the source of truth. Each note can have YAML front matter for its title, tags, and optional description. Directories provide the subject hierarchy; tags connect ideas across subjects.

Source filePage URLRole
docs/index.md/Library overview
docs/aws/networking.md/aws/networkingA knowledge note
docs/akashic/index.md/akashicA subject overview
docs/tags.md/tagsIntroduction to the generated tag index

The app keeps existing relative Markdown links usable. For example, a link from this page to writing-notes.md becomes /akashic/writing-notes. Images may live beside their notes or in docs/assets/.

Preparing the content

scripts/content.mjs scans the Markdown files and prepares data for the app. It:

  1. Parses and validates front matter.
  2. Assigns a URL to each note and checks for conflicting routes.
  3. Extracts headings and anchor IDs for the table of contents.
  4. Extracts plain text for search.
  5. Copies supported assets into public/content/.
  6. Writes the note collection to .generated/library.json.

lib/content.ts imports that generated index and exposes the notes, navigation entries, search data, unique tags, and per-tag note counts. Both .generated/ and public/content/ are disposable outputs excluded from Git. Edit the source files in docs/; the next generation step recreates the outputs.

Pages and shared layout

app/layout.tsx defines the shared header, sidebar, appearance controls, and footer. app/[[...slug]]/page.tsx handles note paths of any depth: it finds the matching note and assembles its tags, content, and table of contents.

The header has Library, Tags, and Search tabs. Library shows the topic tree; Tags shows tag counts with links to sections of the tag index; Search leaves the sidebar empty. The Akashic guides are ordinary Markdown pages in Library. The table of contents includes heading levels 2 through 4, indented by depth.

The same page component adds the collection cards on the Library overview and the grouped listings on the tag index. /search has its own route, which reads the query and selected tag from the URL in the browser.

All note routes are enumerated with generateStaticParams; unknown note routes are not generated on demand. Next.js uses output: "export" and trailing-slash URLs to produce an index.html per route. Search reads URL parameters in a client component behind a Suspense boundary and filters the bundled note data. No request-time server is needed.

Markdown rendering

components/markdown.tsx owns the rendering pipeline. react-markdown parses the Markdown, plugins add syntax support, and our React components determine how the resulting elements appear and behave.

ContentHow it renders
Headings, paragraphs, and listsStandard HTML elements styled by the app
Tables, task lists, and footnotesGitHub-flavored Markdown support
TablesA scrollable container for narrower screens
LaTeX equationsKaTeX, with bundled fonts
Code blocksSyntax highlighting for the common language set plus Dockerfile, and a Copy button
Mermaid blocksDefault-size text, with source and fullscreen controls
Relative Markdown linksLinks to the corresponding app routes
ImagesLocally served assets with alt text

This gives us control over rendering without maintaining a Markdown parser. Raw HTML and executable MDX are currently disabled. New interactions can be implemented as React components and connected to the renderer, following the same approach as Mermaid blocks. Math and diagram dependencies are bundled locally rather than fetched from a CDN.

Server and browser responsibilities

Most page content renders at build time. Components that need user input, browser APIs, or local state run in the browser:

ComponentResponsibility
components/top-navigation.tsxLibrary, Tags, and Search tabs and their active state
components/navigation.tsxTopic tree or tag counts based on the tab, active links, and the mobile menu
components/search.tsxText matching, result lists, and tag filtering
components/theme.tsxSystem appearance and saved light/dark preferences
components/code-block.tsxCopying code to the clipboard
components/mermaid.tsxRendering diagrams, fullscreen viewing, and inspecting their source

Search currently filters the library's searchable text in the browser. It matches query words against titles, tags, and note text, and can restrict results to a selected tag. This keeps the setup small for a personal library. A much larger collection could use a dedicated search index or server endpoint later.

Development and hot reload

With Node.js 22 or newer installed, run:

sh
make env
make dev

make env installs the locked dependencies with npm ci. make dev starts scripts/dev.mjs, which generates the content index, watches docs/, and starts Next.js at http://127.0.0.1:8056.

Adding, editing, or deleting notes updates the content, navigation, and search data. App code also uses Next.js development refresh. Stop the server with Ctrl+C to release port 8056.

For validation and a preview of the static export:

sh
make check
make build
npm start

make check runs tests and TypeScript checks. make build runs scripts/build.mjs, regenerates content, and exports the site to out/; .next/ contains intermediate build files. npm start uses scripts/serve.mjs to preview the exported files on port 8056. Rebuild after changing notes.

make publish runs scripts/publish.mjs: it checks Git remote access, builds with the Pages base path, pushes the export to gh-pages using a temporary checkout, and uses ordinary Git push authentication. Pages is configured once in the repository's web settings; no GitHub CLI is required. Next.js prefixes navigation links; the Markdown renderer explicitly prefixes local image URLs. See publishing instructions.

Where to extend the app

ChangeMain file or directory
Add knowledgedocs/
Adjust the reusable note structuretemplates/note.md
Change typography, spacing, or colorsapp/globals.css
Change the shared application layoutapp/layout.tsx
Change tag placement or the table of contentsapp/[[...slug]]/page.tsx
Customize Markdown elementscomponents/markdown.tsx
Add an interactive widgetcomponents/, then connect it to the renderer
Add metadata processing or indexing behaviorscripts/content.mjs
Change relative-link resolutionlib/paths.mjs

The current app has no database, editing API, or browser-based note editor. Markdown files provide storage, Git provides history, and Next.js provides the reading and interaction layer.
